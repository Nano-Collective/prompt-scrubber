Add locale-aware detector support so rule packs can ship non-English coverage instead of bloating core. Detectors may declare a `locales` field (BCP-47) and then run only when a matching locale is active; detectors without one stay locale-agnostic and always run. A `locale` config key and a `--locale` flag on `scrub`, `inspect` and `watch` select the active locale, with the flag overriding the config. Matching is case-insensitive and crosses subtag levels, so a `de` pack serves `de-DE` and `de-AT`, and a `de-DE` pack answers a `de` request. Locale findings outrank the generic built-in of the same category in collision resolution, letting a locale pack replace an English-biased match, except where that would redact less text than the finding it displaces — a narrower locale match never shrinks an existing redaction — and higher-priority detectors such as `SecretDetector` still win. A malformed `--locale` exits non-zero, and a well-formed locale that activates no detector warns on `stderr` instead of silently scrubbing with English rules only. `locales` coming from a third-party rule pack is validated at load and dropped when it is not an array of strings. `rules list` gains `Locales` and `Locale State` columns — the detector's own default stays in `Default State` — plus a `--locale` option for previewing what another locale would activate. Closes #96.
